# 오류 그룹과 발생 상세

공용 `guardian_report_error()`는 `등급 + 오류 코드 + 파일 + source + failure`의 고정 순서 JSON을 해시로 사용한다. 설명 문구·줄번호·게시판 글 ID는 키에 포함하지 않는다. 저장 쿨다운 내 같은 그룹은 누적 횟수만 증가한다. 쿨다운이 지나면 새 그룹을 만들고 새 발생 상세를 연결한다. 기존 과거 그룹은 합치지 않는다.

`bo_table`과 양의 `wr_id`를 함께 전달하면 `guardian_occurrence`에 발생 시각과 게시판 참조를 저장한다. 게시판 이름은 영문·숫자·밑줄 1~50자만 허용하며 원본 본문·응답을 복제하지 않는다. 특정 사이트나 AI 기능에 의존하지 않는다. 게시판 링크의 열람 권한은 그누보드 게시판에서 검사한다.

## 관리자 화면과 보관

- 오류 상세는 최신순으로 50건씩 조회한다. 다음 페이지는 occurrence_id 커서로 읽는다.
- 테이블이 아직 없으면 설치 업그레이드 안내를 표시한다. 상세가 없으면 업그레이드 전 기록 또는 보관기간 경과 가능성을 안내한다.
- 발생 상세는 `cf_guardian_log_keep_days`(기본 30일)에 따라 발생 시각 기준으로 삭제한다. 미해결 그룹의 상세도 동일하게 만료한다.
- 해결된 그룹만 기존 정책대로 자동 삭제한다. 미해결 그룹과 누적 횟수는 유지한다.
- 관리자가 그룹을 삭제하면 상세도 삭제한다. 남은 고아 참조는 자동 정리에서 재시도한다.
- 상세 만료와 고아 점검은 한 번에 최대 1000건씩 처리한다. 고아 점검 위치는 기존 설정 테이블에 저장하며 동시 정리는 기다리지 않고 건너뛴다.
- 요약 cron 또는 방문자 트리거가 정리한다. 트리거가 실행되지 않거나 적재 속도가 정리 속도보다 빠르면 만료 자료가 남을 수 있다.
- 참조한 게시판 원본 자료는 삭제하지 않는다. 상세 보관기간 때문에 표시 내역과 누적 횟수가 다를 수 있다.

상세 테이블 생성 전에는 글 ID와 게시판 이름을 그룹 메시지에 보존하고, 요청한 상세를 기록하지 못했으므로 보고 API는 false를 반환한다. 그룹 수집과 알림은 계속 처리한다. 업그레이드 후부터 발생별 상세가 쌓이며 과거 기록은 역으로 채우지 않는다. 상세 저장 실패 시 그룹과 알림은 유지하고 실패 참조를 PHP 로그에 기록하며 보고 API는 false를 반환한다.
