# GB Guardian 구조화 오류 보고 API

`guardian_report_error()`는 AI 기능에 종속되지 않은 공용 오류 보고 함수다. `extend/gb_guardian.extend.php`에서 활성화 검사보다 먼저 로드되므로 Guardian 미설치/비활성 상태에서도 PHP 로그를 남길 수 있다. 그누보드 초기화 이후 호출한다.

```php
guardian_report_error(
    'order_processing_failed',
    '주문 처리 결과를 받지 못했습니다.',
    array(
        'source' => 'payment_gateway',
        'failure' => 'transport_error',
        // 게시판에 진단 로그가 있는 경우에만 참조를 추가한다.
        'bo_table' => 'order_diagnostics',
        'wr_id' => (int)$diagnostic_id,
    ),
    E_USER_WARNING,
    __FILE__,
    __LINE__
);
```

## 인자와 그룹 키

- `$error_code`: 고정 오류 식별자. 영문/숫자/`_ . : -`, 1~100자. 설명 문구를 변경할 때도 유지한다.
- `$message`: 사람이 읽는 설명. 그룹 키에는 포함하지 않는다.
- `$context`: `source`, `failure`, `bo_table`, `wr_id`만 수집한다. 인증정보·본문·응답 객체 같은 임의의 필드는 저장하지 않는다.
- `source`, `failure`: 짧은 분류값(64자 이내). 그룹 키에 포함한다. 개인정보 마스킹과 길이 제한을 적용한다. 생략 시 빈 값이다.
- `bo_table`, `wr_id`: 영문/숫자/밑줄로 된 게시판 식별자(1~50자)와 양의 글 ID. 둘 다 유효하면 발생별 참조를 저장한다. 게시판 참조가 없는 일반 오류도 보고할 수 있다.
- `$error_level`: `E_USER_WARNING`(기본), `E_USER_NOTICE`, `E_USER_DEPRECATED`, `E_USER_ERROR`. 기존 수집 등급 설정을 따른다.
- `$file`, `$line`: 호출부 `__FILE__`, `__LINE__`. 생략하면 호출 위치를 자동으로 확인한다.
- 반환값: 그룹과 요청한 발생 상세를 기록했으면 `true`, PHP 로그만 기록했거나 그룹/상세 기록을 실패했으면 `false`. 상세 저장 실패 시 이미 기록한 그룹·횟수와 알림 쿨다운은 유지하고, 실패한 그룹 ID와 상세 참조를 PHP 로그에 명시한다. 오류 보고 함수이므로 반환값으로 업무 요청의 성공/실패를 판단하지 않는다.

그룹 키는 `등급, 오류 식별자, 파일, source, failure`의 고정 순서 JSON이다. 문구·줄번호·게시판 글 ID가 달라도 같은 키이면 기존 저장/알림 쿨다운을 적용한다. 다른 오류 식별자/source/failure/파일/등급은 별도 그룹이다.

## 캡처와 PHP 로그

- 함수는 `guardian_capture()`를 직접 한 번 호출한다. 이어서 `trigger_error()`를 호출하지 않는다. PHP 오류 핸들러를 통하지 않으므로 같은 보고가 두 번 캡처되거나 JSON 응답에 경고 문구가 섞이지 않는다.
- 활성 여부, 수집 등급 필터, DB 기록 성공 여부와 관계없이 `error_log()`로 PHP 로그에 호출당 한 줄을 남긴다. 로그에는 오류 식별자, 등급, 마스킹한 설명, 허용된 상세 참조와 호출 위치를 포함한다. 출력 대상은 PHP의 `error_log` 설정을 따른다.
- Guardian 미설치/비활성/수집 등급 제외 상태에서는 이 API가 DB를 조회하거나 캡처·알림을 실행하지 않는다. 비상정지는 기존 정책대로 알림만 멈추고 수집과 PHP 로그는 계속된다.
- 이 함수는 보고 API이며 PHP 경고 이벤트를 발생시키지 않는다. 기존 외부 오류 핸들러의 콜백도 실행하지 않는다. `E_USER_ERROR`를 사용해도 요청을 종료하지 않으며 종료 여부는 호출자가 결정한다.
- 캡처 예외/엔진 오류는 호출자에게 전파하지 않는다. 오류 로깅 자체가 애플리케이션 응답 흐름을 바꾸지 않도록 한다.
- 같은 해시의 캡처 DB 작업은 요청 간 이름 잠금으로 보호한다. 그룹 잠금은 발송 훅 전에 해제한다. 알림은 DB에 진행 중 예약을 먼저 남겨 동시 요청의 이중 발송을 막는다.
- 오류가 있었던 요청은 종료 시 PHP `error_log`에 `[GB Guardian timing]` JSON 한 줄을 추가한다. 별도 DB 조회/UPDATE나 외부 전송은 하지 않는다. 참조는 최대 5건이며 본문·회원 ID·IP·인증 정보를 복제하지 않는다.
- `request_elapsed_ms`는 `REQUEST_TIME_FLOAT`부터 종료 표시 콜백까지의 PHP 처리 시간이다. 시작값이 없으면 첫 오류부터 측정하고 `start_source=first_error`로 표시한다. 브라우저 왕복 시간이나 PHP 실행 전 웹 서버 대기는 포함하지 않는다. 종료 표시 콜백은 Guardian의 fatal 수집·방문자 정리보다 먼저 등록되며, 그보다 먼저 등록된 다른 종료 콜백이 있다면 그 시간은 포함될 수 있다.
- `shutdown_before_log_ms`는 종료 표시 이후 시간 로그 기록 직전까지의 시간이다. 방문자 정리 등 종료 후 작업이 응답 처리 시간과 섞이지 않도록 별도로 기록한다. 시간 로그보다 나중에 실행되는 종료 작업은 포함되지 않는다.
- `report_ms`는 공용 보고 함수의 누적 시간, `capture_ms`는 오류 캡처·규칙 적용의 누적 시간이다. `group_lock_ms`와 `notify_lock_ms`는 각각 그룹/발송 예약의 `GET_LOCK` 쿼리 시간이며 DB 왕복 시간도 포함한다. 잠금 실패도 측정한다.
- `notify_send_ms`는 실제 채널 어댑터 호출에 걸린 누적 시간이며 실패/예외도 포함한다. `notify_send_attempts`가 0이면 어댑터를 호출하지 않았다(쿨다운 등). 이 값들은 서로 포함 관계이므로 합산해서 전체 시간으로 해석하지 않는다.
- 정상 요청의 추가 작업은 종료 시각 표시 한 번뿐이며 시간 로그는 쓰지 않는다. 오류 요청에서는 메모리 집계와 종료 시 PHP 로그 한 줄을 추가한다. 측정값은 경과 시간이며 CPU 사용량이나 서버 전체 부하량은 아니다.
- 예약의 일일 한도/쿨다운/전역 범위 검사는 짧은 사이트별 DB 잠금 안에서 실행한다. 외부 API를 기다리는 동안 DB 잠금을 유지하지 않는다. 확정 실패는 재시도할 수 있고, 결과 기록 실패는 예약을 유지한다.
- 진행 중 예약은 10분 후 같은 해시의 다음 시도에서 결과 미확인으로 전환한다. 결과 미확인 후의 재시도는 외부 서비스에서 이미 전달했을 가능성이 있어, 네트워크/DB 장애를 포함한 모든 상황의 정확히 1회 전달을 보장하는 API는 아니다.

## 기존 PHP 오류 수집과 배포

기존 `trigger_error()`와 PHP 오류 핸들러는 기존 메시지 기반 그룹화를 유지한다. 문자열의 글 ID나 특정 서비스의 파일명을 분석하지 않는다. 구조화 API를 함께 호출하면 두 개의 보고가 되므로 한 경로만 사용한다.

API·시간 기록·DB·캡처·발송 라이브러리, extend 로더, 설치·관리 화면을 같은 버전으로 배포한다. [DEPLOYMENT.md](DEPLOYMENT.md)의 파일 목록을 참고한다. 발생 상세와 보관 정책은 [OCCURRENCES.md](OCCURRENCES.md)를 참고한다.
